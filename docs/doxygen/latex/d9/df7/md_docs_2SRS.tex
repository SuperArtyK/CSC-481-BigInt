Numbered requirements define the CSC 481 Big\+Integer project. {\bfseries{Required}} features form the core deliverable; {\bfseries{optional}} features are extensions.\hypertarget{md_docs_2SRS_autotoc_md16}{}\doxysection{\texorpdfstring{1. Overview}{1. Overview}}\label{md_docs_2SRS_autotoc_md16}
C++ built-\/in integer types have fixed ranges. This project provides a reusable arbitrary-\/precision signed integer library, {\ttfamily \doxylink{classBigInt}{Big\+Int}}, and a command-\/line calculator, {\ttfamily Evaluator\+Demo}, that demonstrates its operations.

The core {\ttfamily \doxylink{classBigInt}{Big\+Int}} library must be independently usable. The evaluator and optional math module depend on it. A GUI, persistent calculator variables, a full expression parser with precedence or parentheses, and an arbitrary-\/precision fractional type are outside the required scope.

{\bfseries{Terminology.}} A {\itshape limb} represents one base-\/{\ttfamily 10\texorpdfstring{$^\wedge$}{\string^}18} magnitude digit, indexed from zero at the least-\/significant limb. A {\itshape normalized} \doxylink{classBigInt}{Big\+Int} has at least one limb, no redundant most-\/significant zero limbs, and a nonnegative sign if its magnitude is zero. {\itshape Canonical zero} contains exactly one zero limb and has a nonnegative sign. A {\itshape non-\/normalized} representation does not meet these conditions; it may be retained indefinitely. Empty storage is a valid C++ object state but not a normalized numerical representation. The operations permitted on these states are defined in §3.6. {\ttfamily ans} is a predefined calculator result variable, initially zero, with a case-\/insensitive name.\hypertarget{md_docs_2SRS_autotoc_md17}{}\doxysection{\texorpdfstring{2. {\bfseries{Decimal text syntax.}} Valid numeric text permits an optional sign, leading zeroes, one optional decimal point, and leading/\+trailing ASCII spaces or tabs. The input is interpreted as an integer by truncating the fractional part toward zero. For example, {\ttfamily "{} -\/00123.\+45 "{}} converts to {\ttfamily -\/123}, {\ttfamily .5} converts to {\ttfamily 0}, and {\ttfamily 5.} converts to {\ttfamily 5}. Embedded whitespace, commas, exponent syntax, multiple decimal points, and sign-\/only tokens are rejected. Nonempty input must be validated in full.

Empty or ASCII-\/whitespace-\/only strings are invalid {\itshape numeric tokens}, but direct string construction and assignment are special-\/cased to produce zero. Stream extraction requires an actual whitespace-\/delimited token; missing or invalid tokens set the stream failure state and preserve the destination.

{\bfseries{Display versus exact conversion.}} {\ttfamily to\+String()} and the default {\ttfamily operator\texorpdfstring{$<$}{<}\texorpdfstring{$<$}{<}} are for human-\/readable display and may emit rounded scientific notation for values exceeding 20 decimal digits. Such display text is not guaranteed to be accepted by the current numeric-\/string parser or to preserve the original value if parsed. {\ttfamily to\+String\+Dec()} always produces the exact, lossless decimal representation; for every {\bfseries{normalized}} \doxylink{classBigInt}{Big\+Int} value {\ttfamily x}, constructing a \doxylink{classBigInt}{Big\+Int} from {\ttfamily x.\+to\+String\+Dec()} shall reconstruct the same mathematical value. The current parser {\bfseries{does not accept scientific/\+exponent notation}}.\hypertarget{md_docs_2SRS_autotoc_md20}{}\doxysubsection{\texorpdfstring{3.\+2 Arithmetic and comparisons}{3.\+2 Arithmetic and comparisons}}\label{md_docs_2SRS_autotoc_md20}

A valid \doxylink{classBigInt}{Big\+Int} C++ object may have a normalized representation, a non-\/normalized representation, or {\bfseries{no stored limbs}}. In particular, numerical operations are not required to check or report missing normalization.

{\bfseries{Negative zero and raw storage.}} Directly setting the sign of zero, or raw limb manipulation, may produce negative zero. {\ttfamily is\+Negative()} reports the actual sign flag; {\ttfamily is\+Normalised()} reports {\ttfamily false}. Normalizing zero clears the sign. A nonzero actual {\ttfamily set\+Limb()} write preserves the prior sign, including from negative zero, while an out-\/of-\/range zero no-\/op does not modify anything. {\ttfamily set\+Limb\+Raw()} never implicitly normalizes and may preserve redundant zero limbs indefinitely.

{\bfseries{Moved-\/from and empty representations.}} After a successful ordinary move, the destination preserves the transferred pre-\/move limb sequence and sign. The moved-\/from source remains valid, and its current state can be inspected using the Category A operations whose preconditions are met. A copy of that source preserves exactly the state that remains, even when the limb sequence is empty; copying empty storage is {\bfseries{not}} undefined behavior. {\ttfamily get\+First\+Limb()} and {\ttfamily get\+Last\+Limb()} always require nonempty storage. {\ttfamily normalise()} restores empty storage to canonical zero upon success; for nonempty storage it normalizes the remaining magnitude rather than guaranteeing that a moved-\/from source becomes zero. {\ttfamily set\+To\+Zero()} restores canonical zero upon success. Restoration may fail due to resource exhaustion.

{\bfseries{Self-\/assignment and failures.}} Self-\/copy assignment preserves the representation. Self-\/move assignment is a nonthrowing, complete no-\/op even for non-\/normalized, negative-\/zero or empty states. Invalid input and domain errors must preserve the existing representation; resource exceptions need preserve only a valid C++ object, potentially with empty storage. After such a failure, callers must establish the relevant preconditions before numerical use. Neither successful restoration nor memory allocation is guaranteed under resource exhaustion.

{\bfseries{Boundary behavior.}} {\ttfamily set\+Limb()} and {\ttfamily set\+Limb\+Raw()} shall prevent overflow when calculating the storage size needed for an extension. An out-\/of-\/range zero write through {\ttfamily set\+Limb()} remains a successful no-\/op, including at the largest representable index. {\ttfamily get\+Digit\+Count()} shall report {\ttfamily 0} when the exact digit count is not representable, as specified by FR-\/\+BI-\/039.\hypertarget{md_docs_2SRS_autotoc_md25}{}\doxysection{\texorpdfstring{4. {\bfseries{Unary/\+binary disambiguation.}} At the beginning of an operand (the beginning of an evaluation or immediately following a binary operator), a single {\ttfamily +} or {\ttfamily -\/} is a unary sign {\bfseries{only when directly attached}} to a literal or identifier.
