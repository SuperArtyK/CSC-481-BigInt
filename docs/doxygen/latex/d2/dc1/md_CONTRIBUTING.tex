We use {\bfseries{feature branches, pull requests, code reviews, and automated tests}} to maintain the project.\hypertarget{md_CONTRIBUTING_autotoc_md11}{}\doxysection{\texorpdfstring{Development workflow}{Development workflow}}\label{md_CONTRIBUTING_autotoc_md11}

\begin{DoxyEnumerate}
\item {\bfseries{Create a branch.}} Start from an up-\/to-\/date {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}}. Use a separate branch for each feature, bug fix, or task.
\item {\bfseries{Develop and commit.}} Make focused changes and commit regularly. Push your branch to Git\+Hub whenever needed.
\item {\bfseries{Build and test.}} Verify that the project builds and all relevant CTest tests pass locally before requesting review. Add or update unit tests when changing functionality.
\item {\bfseries{Open a pull request.}} Target {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}}, describe your changes, reference relevant issues, and explain how you tested them. Use a draft PR if the changes aren\textquotesingle{}t ready for review.
\item {\bfseries{Review and revise.}} Discuss feedback in the PR. Make corrections on the same branch and push them to update the PR automatically.
\item {\bfseries{Merge.}} Merge only after the team agrees, review requirements are met, all discussions are resolved, and CI passes. Merge through the Git\+Hub or CLion PR interface, not by pushing directly to {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}}.
\end{DoxyEnumerate}

After merging, delete the completed feature branch when no longer needed and update your local {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}}.\hypertarget{md_CONTRIBUTING_autotoc_md12}{}\doxysection{\texorpdfstring{Testing requirements}{Testing requirements}}\label{md_CONTRIBUTING_autotoc_md12}

\begin{DoxyItemize}
\item {\bfseries{All automated tests must pass}} before merging, including the required Git\+Hub CI checks.
\item Git\+Hub Actions builds and tests the project using GCC, Clang, and MSVC across Debug/\+\+ASan and Release configurations.
\item New functionality and bug fixes should include appropriate unit tests.
\item Tests belong in the relevant subproject\textquotesingle{}s {\ttfamily tests/} directory and are automatically discovered through CMake and Google\+Test.
\item Playground {\ttfamily main.\+cpp} files are for development and experimentation. They must compile successfully but are not executed by automated CI.
\end{DoxyItemize}\hypertarget{md_CONTRIBUTING_autotoc_md13}{}\doxysection{\texorpdfstring{Code review}{Code review}}\label{md_CONTRIBUTING_autotoc_md13}

\begin{DoxyItemize}
\item Everyone should review proposed changes or explicitly indicate that they have no objections.
\item At least {\bfseries{one approval}} is required by repository rules. This is a minimum, not a substitute for team agreement.
\item Do not merge while there are unresolved objections or requested changes.
\item Keep review discussions in the pull request so decisions remain visible.
\item Do not modify or push to another contributor\textquotesingle{}s branch without their agreement.
\end{DoxyItemize}\hypertarget{md_CONTRIBUTING_autotoc_md14}{}\doxysection{\texorpdfstring{Repository rules}{Repository rules}}\label{md_CONTRIBUTING_autotoc_md14}

\begin{DoxyItemize}
\item Do not directly push ordinary development changes to {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}}.
\item Do not force-\/push to {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}} or bypass the normal review process.
\item The repository owner retains an administrative bypass for exceptional maintenance or recovery, but follows the same PR and review process during normal development.
\item Prefer small, focused pull requests that are straightforward to review and test.
\end{DoxyItemize}
