A practical guide to Git, pull requests, and automated testing in CLion. For team rules and contribution requirements, see \doxysectlink{md_CONTRIBUTING}{Contributing}{0}.

{\bfseries{Normal workflow:}} Create branch → Develop → Build/\+test → Commit → Push → Pull request → Review → Merge.

{\bfseries{Remember:}} Commit saves changes locally. Push uploads commits to Git\+Hub. Neither automatically creates a pull request.\hypertarget{md_CLION__WORKFLOW_autotoc_md1-create-a-feature-branch}{}\doxysection{\texorpdfstring{1. Create a feature branch}{1. Create a feature branch}}\label{md_CLION__WORKFLOW_autotoc_md1-create-a-feature-branch}

\begin{DoxyEnumerate}
\item Use the branch widget in CLion to switch to {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}}.
\item Update it using {\bfseries{Git → Update Project}} ({\ttfamily Ctrl+T}).
\item Open the branch widget and select {\bfseries{New Branch from \textquotesingle{}main\textquotesingle{}}}.
\item Enter a descriptive name, such as {\ttfamily feature/\+addition} or {\ttfamily fix/\+division}.
\item Enable {\bfseries{Checkout branch}} and create the branch.
\end{DoxyEnumerate}

Confirm that the new branch is selected before making changes.

{\bfseries{Important:}} If you already have uncommitted changes, commit or safely preserve them before switching branches. You can also create and check out a new branch from your current branch to carry those changes over.\hypertarget{md_CLION__WORKFLOW_autotoc_md2-build-and-run-tests}{}\doxysection{\texorpdfstring{2. Build and run tests}{2. Build and run tests}}\label{md_CLION__WORKFLOW_autotoc_md2-build-and-run-tests}
Before committing or requesting review:


\begin{DoxyEnumerate}
\item Select a CMake profile compatible with your compiler, such as {\ttfamily gcc-\/native-\/debug}.
\item Build the project using {\bfseries{Build → Build Project}} ({\ttfamily Ctrl+\+F9}).
\item In the Run/\+\+Debug configuration selector, choose {\bfseries{All CTest}} and click {\bfseries{Run}} ({\ttfamily Shift+\+F10}).
\item Inspect the results in the test runner. All tests should pass.
\end{DoxyEnumerate}

If {\ttfamily All CTest} isn\textquotesingle{}t available, reload CMake or look under {\bfseries{Run → Edit Configurations → CTest Application}}. Ensure the configuration builds the necessary test targets (usually {\bfseries{All targets}}) before running.\hypertarget{md_CLION__WORKFLOW_running-individual-tests}{}\doxysubsection{\texorpdfstring{Running individual tests}{Running individual tests}}\label{md_CLION__WORKFLOW_running-individual-tests}

\begin{DoxyItemize}
\item Click the gutter icon beside a Google\+Test {\ttfamily TEST(...)} function to run or debug that test.
\item Use {\bfseries{Rerun Failed Tests}} in the test runner to repeat failures.
\item When adding tests, place new {\ttfamily .cpp} files under the appropriate module\textquotesingle{}s {\ttfamily tests/} directory. CMake discovers them automatically.
\item Google\+Test is downloaded by CMake; no separate installation is needed.
\end{DoxyItemize}

The playground executables ({\ttfamily \doxylink{classBigInt}{Big\+Int}}, {\ttfamily Big\+Int\+\_\+\+Math}, {\ttfamily Evaluator\+Demo}) can be run separately using their own configurations. CTest does not execute these playgrounds.\hypertarget{md_CLION__WORKFLOW_autotoc_md3-commit-and-push-changes}{}\doxysection{\texorpdfstring{3. Commit and push changes}{3. Commit and push changes}}\label{md_CLION__WORKFLOW_autotoc_md3-commit-and-push-changes}

\begin{DoxyEnumerate}
\item Open {\bfseries{Commit}} ({\ttfamily Alt+0}).
\item Review the diff and select the intended files.
\item Enter a descriptive commit message and click {\bfseries{Commit}}.
\item Choose {\bfseries{Git → Push}} ({\ttfamily Ctrl+\+Shift+K}).
\item Verify that the destination is {\ttfamily origin/\+your-\/branch-\/name}, {\bfseries{not {\ttfamily origin/\+main}}}.
\item Click {\bfseries{Push}}.
\end{DoxyEnumerate}

You can make multiple commits and pushes on the same branch. Uncommitted changes are never included in a push.\hypertarget{md_CLION__WORKFLOW_autotoc_md4-create-a-pull-request}{}\doxysection{\texorpdfstring{4. Create a pull request}{4. Create a pull request}}\label{md_CLION__WORKFLOW_autotoc_md4-create-a-pull-request}

\begin{DoxyEnumerate}
\item Push your feature branch.
\item Choose {\bfseries{Git → Git\+Hub → Create Pull Request}}, or open the repository on Git\+Hub.
\item Set the base branch to {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}} and the head branch to your feature branch.
\item Provide a title, a description of the changes, and how you tested them.
\item Request team review. Use a {\bfseries{draft PR}} for unfinished work.
\end{DoxyEnumerate}

New commits pushed to the feature branch automatically update the existing PR.

Git\+Hub Actions runs CI for pull requests targeting {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}}. Check the workflow results and resolve failures before merging.\hypertarget{md_CLION__WORKFLOW_autotoc_md5-review-someone-elses-pull-request}{}\doxysection{\texorpdfstring{5. Review someone else\textquotesingle{}s pull request}{5. Review someone else\textquotesingle{}s pull request}}\label{md_CLION__WORKFLOW_autotoc_md5-review-someone-elses-pull-request}

\begin{DoxyEnumerate}
\item Open {\bfseries{Git → Git\+Hub → View Pull Requests}}.
\item Select the PR and examine its changed files and discussion.
\item Submit your review using {\bfseries{Approve}}, {\bfseries{Request Changes}}, or {\bfseries{Comment}}.
\end{DoxyEnumerate}

To compile or test the changes without disturbing your current work, use a separate worktree:


\begin{DoxyEnumerate}
\item Choose {\bfseries{Git → Fetch}} to update remote branch information.
\item Open {\bfseries{Git ({\ttfamily Alt+9}) → Worktrees → New Worktree}}.
\item Select the PR branch, typically {\ttfamily origin/\+feature-\/name}.
\item Choose a directory outside your existing project.
\item Open the new worktree in CLion and build/\+test it normally.
\end{DoxyEnumerate}

The worktree has its own working files, so your original project\textquotesingle{}s uncommitted changes remain untouched. Do not push experimental changes to the author\textquotesingle{}s branch without permission.\hypertarget{md_CLION__WORKFLOW_autotoc_md6-merge-and-finish}{}\doxysection{\texorpdfstring{6. Merge and finish}{6. Merge and finish}}\label{md_CLION__WORKFLOW_autotoc_md6-merge-and-finish}
When the team agrees, the required approvals are present, review discussions are resolved, and {\bfseries{CI / Required}} passes:


\begin{DoxyEnumerate}
\item Merge using the pull request interface in CLion or Git\+Hub.
\item Delete the completed feature branch when no longer needed.
\item Remove temporary review worktrees after confirming that they contain no work you need to keep.
\item Switch back to {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}} and update it before starting another task.
\end{DoxyEnumerate}

Do not merge locally into {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}} and push it as a substitute for a reviewed PR.\hypertarget{md_CLION__WORKFLOW_safety-reminders}{}\doxysection{\texorpdfstring{Safety reminders}{Safety reminders}}\label{md_CLION__WORKFLOW_safety-reminders}

\begin{DoxyItemize}
\item Check your current branch before committing or pushing.
\item Avoid switching branches with uncommitted changes unless you understand how Git will handle them.
\item Never force-\/push to {\ttfamily \doxylink{BigInt_2main_8cpp_ae66f6b31b5ad750f1fe042a706a4e3d4}{main}}.
\item Reviewing a PR doesn\textquotesingle{}t require checking out its branch.
\item Use separate worktrees when testing other contributors\textquotesingle{} changes.
\item Do not commit local build output or CLion workspace settings.
\end{DoxyItemize}\hypertarget{md_CLION__WORKFLOW_references}{}\doxysection{\texorpdfstring{References}{References}}\label{md_CLION__WORKFLOW_references}
